# 测试说明

本文档描述「公司X光守护」应用的测试方法和测试场景，供开发人员和测试人员验证应用功能是否正常。

---

## 测试前准备

### 设备要求

- Android 7.0 及以上版本的手机一台
- 手机已安装微信、支付宝等至少一款支付类应用
- 建议使用真机测试（模拟器的无障碍服务可能不稳定）

### 安装应用

1. 按照 [BUILD.md](./BUILD.md) 中的说明构建 Debug APK
2. 通过 ADB 或其他方式安装到测试手机
3. 确认应用图标出现在桌面

### 授权步骤（必须完成）

首次启动应用后，需要按照引导页完成以下权限授权：

#### 1. 无障碍权限（核心权限）

1. 在引导页点击「开启无障碍服务」
2. 跳转到系统「无障碍」设置页面
3. 在「已下载的服务」或「更多已下载的服务」中找到「公司X光守护」
4. 点击进入，打开开关
5. 在弹出的确认对话框中点击「允许」或「确定」
6. 返回应用，确认该权限状态变为「已开启」

> 不同品牌手机的无障碍设置路径可能不同：
> - 小米：设置 → 更多设置 → 无障碍 → 公司X光守护
> - 华为：设置 → 辅助功能 → 无障碍 → 公司X光守护
> - OPPO：设置 → 其他设置 → 无障碍 → 公司X光守护
> - 三星：设置 → 辅助功能 → 已安装的应用 → 公司X光守护

#### 2. 悬浮窗权限

1. 在引导页点击「开启悬浮窗权限」
2. 跳转到系统设置页面
3. 打开「允许显示在其他应用的上层」开关
4. 返回应用，确认该权限状态变为「已开启」

#### 3. 通知权限

1. 在引导页点击「开启通知权限」
2. 在弹出的系统对话框中点击「允许」
3. 确认该权限状态变为「已开启」

#### 4. 开机自启（可选，推荐开启）

1. 在引导页或设置页找到「开机自启」选项
2. 跳转到系统设置，允许应用自启动
3. 该权限确保手机重启后守护服务自动运行

#### 5. 电池优化白名单（可选，推荐设置）

为防止系统杀死后台服务，建议将应用加入电池优化白名单：

- **小米**：设置 → 电池与性能 → 电池 → 应用智能省电 → 公司X光守护 → 无限制
- **华为**：设置 → 电池 → 启动管理 → 公司X光守护 → 手动管理 → 允许自启动/后台活动
- **OPPO**：设置 → 电池 → 应用耗电管理 → 公司X光守护 → 允许完全后台行为
- **三星**：设置 → 电池和设备维护 → 电池 → 后台使用限制 → 从不休眠的应用 → 添加公司X光守护

### 验证服务运行状态

完成授权后，在应用主页查看：

- 守护状态应为「运行中」（绿色）
- 无障碍权限显示「已授权」
- 悬浮窗权限显示「已授权」

如果状态异常，请重新检查授权步骤。

## 测试场景一：硬红高危（雪王冻品）

### 场景说明

「雪王冻品」是一个模拟的高风险山寨商家名称，与知名品牌「蜜雪冰城」高度相似但并非正规品牌，应触发**红色高危**告警。

### 测试步骤

1. 确保应用已启动且守护服务运行中
2. 打开任意支付类应用（微信/支付宝等）
3. 进入支付/付款页面，在收款方/商家名称处模拟出现「雪王冻品」字样
4. 或在设置中使用「模拟测试」功能（如有），输入商家名称「雪王冻品」，金额 500 元

> 如果无法直接在真实支付页面测试，可通过开发者选项中的模拟测试功能验证。

### 预期结果

- 屏幕上弹出**全屏红色悬浮窗**，显示高危告警
- 悬浮窗内容包含：
  - 警示标题：「风险提醒！向高风险商家付款请谨慎」
  - 商家名称：雪王冻品
  - 风险等级：高危（红色）
  - 风险原因：与知名品牌「蜜雪冰城」名称高度相似，疑似山寨
  - 交易金额：￥500.00
- 手机产生**强振动**提醒
- 状态栏出现通知提醒
- 用户必须点击「我已知晓风险」才能关闭悬浮窗
- 告警记录保存到本地历史记录中

### 验证方法

1. 观察悬浮窗是否及时弹出（页面出现后 1-3 秒内）
2. 检查风险等级是否正确显示为红色高危
3. 检查商家名称和金额是否正确提取
4. 返回应用主页 → 告警历史，确认该条记录已保存

## 测试场景二：黄色关注（鹿角湾）

### 场景说明

「鹿角湾」是一个模拟的中等风险商家名称，与知名奶茶品牌「鹿角巷」名称相近，存在一定蹭名嫌疑，应触发**黄色关注**级别的提醒。

### 测试步骤

1. 确保守护服务运行中
2. 在支付页面或模拟测试中，输入商家名称「鹿角湾」，金额 200 元
3. 观察应用的反应

### 预期结果

- 屏幕顶部出现**黄色悬浮条**，显示关注提醒
- 悬浮条内容包含：
  - 提示文字：「注意：该商家名称与知名品牌相似，请确认」
  - 商家名称：鹿角湾
  - 风险等级：关注（黄色）
  - 点击可查看详情
- 振动较弱或无振动（根据设置）
- 状态栏出现通知提醒
- 悬浮条几秒后自动消失，或用户可手动滑走
- 告警记录保存到本地历史记录中

### 验证方法

1. 观察黄色悬浮条是否正确显示
2. 确认不会弹出全屏红色悬浮窗（黄色级别不应强打断）
3. 点击悬浮条可查看详情页
4. 在告警历史中可看到该条记录，标记为黄色关注

## 测试场景三：绿色正常（蜜雪冰城）

### 场景说明

「蜜雪冰城」是正规知名品牌，存在于品牌库的白名单中，应判定为**绿色正常**，不打扰用户。

### 测试步骤

1. 确保守护服务运行中
2. 在支付页面或模拟测试中，输入商家名称「蜜雪冰城」，金额 30 元
3. 观察应用的反应

### 预期结果

- **不弹出任何悬浮窗**，不干扰用户正常支付
- 状态栏**不出现**告警通知
- 手机**不振动**
- 可选：在应用的检测日志中可以看到本次检测记录（标记为绿色正常），但不会出现在告警历史中

### 验证方法

1. 确认支付过程中没有悬浮窗干扰
2. 检查通知栏没有新的告警通知
3. 进入告警历史，确认没有新增红色或黄色记录
4. （如有检测日志功能）在日志中可看到「蜜雪冰城 - 绿色正常」的记录

## 测试场景四：投资场景

### 场景说明

当检测到投资、理财、返利等关键词时，即使商家名称不在风险库中，也应触发更高等级的风险提醒。投资场景本身就具有较高风险属性。

### 测试步骤

1. 确保守护服务运行中
2. 模拟以下任一投资场景：
   - 商家名称包含「投资」「理财」「基金」「股票」「返利」「高收益」等关键词
   - 页面场景被识别为投资/理财类页面
3. 输入金额 5000 元
4. 观察应用的反应

### 预期结果

- 触发**黄色关注**或**红色高危**（根据金额和关键词数量）
- 悬浮窗/悬浮条显示投资风险提示：
  - 提示内容：「投资有风险，高额返利需谨慎」
  - 明确标注「投资场景」
  - 提醒用户核实平台资质
- 金额超过阈值（如 2000 元）时升级为红色高危
- 告警记录保存，并标记为「投资」类别

### 验证方法

1. 确认投资关键词被正确识别
2. 验证金额阈值逻辑：
   - 小额（如 100 元）应为黄色关注
   - 大额（如 5000 元）应为红色高危
3. 检查告警历史中是否正确标记了场景类型

## 测试场景五：家人绑定与通知

### 场景说明

用户可以绑定家人账号，当发生高危告警时，家人也会收到通知。此场景测试绑定流程和通知推送功能。

### 测试准备

- 需要两台手机：一台安装守护端（本应用），一台安装家人管理端
- 或使用一台手机配合管理后台网页版
- 两台设备均需联网

### 测试步骤

#### 5.1 绑定家人

1. 打开「公司X光守护」应用
2. 进入「家人守护」或「家人绑定」页面
3. 点击「绑定家人」
4. 生成绑定二维码或绑定码
5. 在家人端应用中扫描二维码或输入绑定码
6. 确认绑定成功

#### 5.2 验证通知推送

1. 确保两台设备均联网
2. 在守护端触发一次红色高危告警（如场景一的「雪王冻品」）
3. 观察家人端是否收到通知

### 预期结果

#### 绑定阶段
- 二维码/绑定码生成成功
- 家人端扫描/输入后，双方均显示绑定成功
- 守护端的家人列表中显示已绑定的家人信息

#### 通知阶段
- 高危告警发生后 10 秒内，家人端收到推送通知
- 通知内容包含：
  - 告警标题：「您的家人可能正在向高风险商家付款」
  - 商家名称、金额、时间
  - 风险等级
- 家人端可查看告警详情和历史记录
- 用户可在守护端随时解绑家人

### 验证方法

1. 在守护端确认绑定成功，家人列表正确显示
2. 触发高危告警后，检查家人端是否收到通知
3. 检查通知内容是否完整准确
4. 测试解绑功能：解绑后再次触发告警，家人端不应再收到通知
5. 测试关闭家人通知开关：关闭后即使已绑定也不推送

## 已知问题与不支持的场景

### 已知问题

| 问题 | 影响范围 | 严重程度 | 说明 |
|------|----------|----------|------|
| 部分页面商家名称提取不准确 | 中等 | 中 | 某些支付页面的商家名称位于图片中，无法通过无障碍服务读取 |
| 悬浮窗在部分全屏应用中不显示 | 低 | 中 | 全屏游戏、视频应用可能遮挡悬浮窗 |
| 服务在后台被系统杀死 | 高 | 高 | 国产 ROM 的电池优化策略导致服务不稳定，需手动加白名单 |
| 微信小程序内支付页面识别率低 | 中等 | 中 | 小程序页面结构特殊，部分字段难以提取 |

### 不支持的场景

以下场景目前**不支持**或**识别率极低**，测试时请知悉：

1. **使用 FLAG_SECURE 的应用**：银行 App、部分证券 App 等开启了安全窗口保护，无障碍服务无法读取内容
2. **纯图片形式的支付页面**：商家名称和金额全部显示在图片上，文本提取不可靠
3. **智能手表/平板等非常规设备**：仅针对手机形态优化
4. **多用户/工作资料模式**：在工作资料空间中安装的应用可能无法被监测
5. **iOS 设备**：本应用仅支持 Android 平台
6. **境外支付应用**：品牌库主要覆盖国内常见商家，境外商家识别率低
7. **系统级支付（如运营商扣款）**：不走常规支付页面流程

### 调试建议

如果测试中遇到问题，可以通过以下方式排查：

1. **查看 Logcat 日志**：
   ```powershell
   adb logcat -s CompanyXray
   ```

2. **确认无障碍服务是否运行**：
   - 进入系统设置 → 无障碍 → 查看「公司X光守护」开关状态
   - 如果开关自动关闭，通常是服务崩溃或被系统杀死

3. **检查悬浮窗权限**：
   - 在应用内查看权限状态
   - 部分 ROM 需要单独授权悬浮窗权限

4. **清除数据重试**：
   - 设置 → 应用 → 公司X光守护 → 存储 → 清除数据
   - 重新走一遍授权流程
