# 公司投资评分 · X光透视

普通投资者用的公司投资评估工具：输入公司名，联网抓取数据后按十维加权打分，输出投资结论（≥58 分即「目前适合投资」），并可生成一份可打印的完整评估报告。

## 运行

```bash
# 需 Node 18+（内置 fetch），本机用：
C:/Users/WQJY/.workbuddy/binaries/node/versions/22.22.2-3/node.exe server.js
# 浏览器打开 http://localhost:3210
```

零 npm 依赖，无需 install。

## 十维评分与权重

维度：行业 / 团队 / 技术 / 产品 / 成本 / 管理 / 客户 / 品牌 / 财务安全 / 诉讼风险

两套权重口径：

| 类型 | 权重最高项 |
|---|---|
| 上市公司（稳健型） | 财务安全 18 > 产品 15 > 行业/技术/成本/客户 10 > 团队/品牌 8 > 诉讼 6 > 管理 5 |
| 未上市公司（成长型） | 产品 18 > 行业 15 > 技术/团队/客户/财务 12 > 成本 6 > 品牌 5 > 诉讼 4 > 管理 4 |

## 判定规则

| 分数区间 | 结论 | 颜色 |
|---|---|---|
| > 50 | 目前适合投资 | 绿 |
| ≤ 50 | 目前看来并不是非常适合投资 | 红 |

精英背景不直接改变结论档位：每检出 1 名精英人物（大厂履历 + 专业提及双标记齐全）总分 +1，封顶 +5，可能把 50 分附近的公司托过投资线。

精英判定来源：① 内置知名企业家库（雷军/王传福/曾毓群等 24 人，公开常识）② 工商董监高/核心成员逐人联网核查双标记（大厂履历 + 专业提及）③ 未命中时如实标注"未检索到不等于不存在"。

## 数据渠道（全部带超时降级，单渠道失败不影响整体）

| 渠道 | 用途 | 说明 |
|---|---|---|
| 企查查 / 水滴信用 MCP | 工商登记 / 股东 / 主要人员 / 实控人 | 可选：`mcp.local.json` 或 `QCC_MCP_TOKEN` / `SHUIDI_MCP_TOKEN` 配置后启用，三级数据源第一优先级 |
| 东方财富 suggest | 上市公司代码匹配 | 按股票简称连续子串匹配（支持公司全称滑窗找回），公开接口 |
| 东方财富 F10 三表 | 资产负债率 / 货币资金 / 应收 / 毛利率 / 净利率 | 真实财报数据，最近报告期 |
| 东方财富 F10 股东研究/公司治理 | 十大股东 / 实际控制人 / 董监高名单（含简历） | 公开接口，A 股；未配置 MCP 时的工商数据主渠道 |
| 腾讯行情 qt.gtimg.cn | 现价佐证 | GBK 编码已处理 |
| 必应 site:aiqicha/qcc | 法定代表人交叉核验 | 从公开摘要解析，与用户填写不一致时警示 |
| 必应检索 | 新闻 / 诉讼 / 专利 / 中标等信号 | 按关键词映射到对应维度修正基础分 |

### 工商股权数据的三级数据源

1. **MCP Connector 直连**（可选）：在项目根目录建 `mcp.local.json`：
   ```json
   { "qcc": { "token": "企查查MCP的Bearer Token" }, "shuidi": { "token": "水滴信用MCP的Bearer Token" } }
   ```
   （或设置环境变量 `QCC_MCP_TOKEN` / `SHUIDI_MCP_TOKEN`。）企查查走 `get_company_registration_info` / `get_shareholder_info` / `get_key_personnel` / `get_actual_controller`；水滴走 `get_company_info` / `get_company_partner` / `get_company_employee`。
2. **东方财富 F10 公开接口**（默认生效，零配置）：A 股自动拉取十大股东（报告期）、实际控制人、董监高名单（含法定代表人标注与高管简历）。
3. **公开搜索索引兜底**：必应 site 检索解析法定代表人摘要。

结果页新增「工商登记与股权档案」卡片：法定代表人、实际控制人、信用代码、注册资本、股东构成表（一层直接持股，比例按数据源原样引用）、主要人员（含简历）。持股比例数据纪律：逐字引用，不做穿透推算；实控人仅引用专门接口返回值。

## 数据可信度设计

- 真实财务数据优先级最高，命中演示样本的公司其财务维度也不会被演示数据覆盖
- 任一渠道失败 → 该维度按中性分 50 处理并在"数据渠道状态"卡中如实标注
- 未命中内置样本且渠道受限时 → 页面顶部显示"演示模式"黄条
- 页脚固定免责声明：仅供参考，不构成投资建议

## 评估报告（细分版）

结果页底部有「📄 生成完整评估报告」，把评分过程写成一份可打印的文档（也支持下载为 HTML 归档）。

报告解决的是"分数从哪来、算得对不对"这两个问题，因此定下三条硬约束：

1. **每维都要能核对**：标出分数出处（财报指标计算 / 内置演示样本 / 新闻信号修正 / 缺省中性）、
   有效权重（按有实分的维度归一到 100%）、以及该维对总分的**贡献分**。
   把贡献分一列全部相加，必须等于十维加权平均分 —— `test/smoke-report.js` 会断言这一点。
2. **计算链逐步列出**：十维 → 上市公司折算 80% → 股票评估 20% → 精英人物加分 → 综合得分，
   每步都写算式与结果，末尾给"自洽校验"（重算值 vs 引擎输出）。不一致会显式报出来，不掩盖。
3. **没数据就说没数据**：未取得实分的维度标「未评分」并**排除在加权分母之外**（不是按 0 分计入），
   摘要里单独点名是哪几维 —— 否则读者会把"没查到"误读成"这维表现差"。

八章顺序：结论摘要 / 评分方法与算法 / 十维逐项分析 / 股票投资评估 / 股权结构与人员 /
数据完备性与局限 / 风险提示 / 免责声明。未上市或无工商数据的公司会自动少节并重排编号。

## 结构

```
invest-score-app/
├── server.js          # HTTP 服务 + API（零依赖）
├── lib/
│   ├── sources.js     # 联网数据源聚合层
│   ├── registry.js    # 工商股权三级数据源（MCP → 东财F10 → 公开索引）
│   ├── scoring.js     # 十维加权打分 + 三档判定
│   ├── report.js      # 完整评估报告（逐维出处 + 贡献分 + 计算链 + 自洽校验）
│   ├── elite.js       # 行业精英三级判定
│   ├── analyze.js     # 分析编排（并行抓取 → 维度合成 → 打分 → 出报告）
│   └── seed.js        # 内置演示样本（降级兜底，页面显著标注）
├── public/
│   └── index.html     # 前端单页（双入口 + 弹窗 + 三色结论 + 工商股权档案卡 + 报告视图）
└── test/
    ├── smoke-registry.js  # registry 层冒烟
    ├── smoke-report.js    # 报告自洽性（贡献分合计 / 计算链 / 缺失维度口径，不联网）
    └── smoke-e2e.js       # analyze 全链路
```
